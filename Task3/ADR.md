### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Как альтернатива можно вынести приём заявок в новый сервис со своей БД, который будет являться транспортом для заявок. 
АБС будет вызывать только асинхронно, менеджер работает в отдельном UI. 
Менеджер бэк-офиса в UI подтверждает ставку/условия, после этого передается команда на открытие депозита в АБС.
Минусом такого решения является, что возможно менеджеру приедтся работать в двух интерфейсах: АБС и UI для обработки заявки

**Недостатки, ограничения, риски**
* Низкое время обработки заявки, т.к ее по прежнему обрабатывают вручную бэк-офис. В пике нагрузки будут сильные задержки, жалобы от клиентов
* В этом решении клиент просто отправляет форму для заявки и дальше не может заявку отслеживать, только в конце получает СМС. Поэтому есть риск что клиент повторно создат заявку, будет дублирование
* Данный вариант защищает АБС от прямых API-вызовов из ИБ, но бэк-офис всё равно массово подтверждает в АБС, что не снижает нагрузки с АБС
* Сложно померить конверсию по шагам, причины отказов, время на этапах
